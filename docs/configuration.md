# Mini 配置说明

[返回仓库首页](../README.md)

本页对应 v0.3.4 公版。已有安装可能保留自己的规则和参数，实际以面板、配置文件与运行版本为准。

## 聊天节奏

| 预设 | 最短–最长间隔 | 前段权重 | 中段权重 | 尾段起点 | 尾段下限 | 尾段衰减 |
| --- | --- | --- | --- | --- | --- | --- |
| 偶尔聊 | 60–480 分钟 | 0.6 | 1.0 | 1.3 | 0.8 | 0.4 |
| 默认 | 5–240 分钟 | 1.0 | 1.15 | 1.15 | 0.6 | 0.3 |
| 稍微有点粘人 | 5–150 分钟 | 1.5 | 1.2 | 1.0 | 0.45 | 0.25 |
| 粘人 | 3–60 分钟 | 2.0 | 1.3 | 0.8 | 0.3 | 0.2 |

间隔范围切成前、中、尾三段，按各段权重采样。尾段逐渐向下限衰减。有事件时，前段还会乘 `early_weight_event`（默认 3.0）。它们控制权重，不保证精确多久发一条；睡眠、约定、事件和正常回复避让可继续调整排程。

手动修改参数后，预设显示为「自定义」。概率页的柱形图是预览，点击保存后才写入配置。默认未回复上限 `max_unanswered_times=3`，达到后暂停常规主动消息；设为 0 表示不限，会增加无人回复时的生成与发送量。

## 活动与在场

默认配置包含 16 类事件，文件回退模板有 8 类。每条规则可配置触发词、结束词、`ttl_minutes`、`boost`、`boost_budget` 与事件提示词。提示词支持 `{elapsed}`、`{label}`；加成预算默认 1，0 表示不限次。规则变更需要重载插件。

规则包含主体、否定、疑问、引用、条件和未来表达保护，不能把它简单理解成「出现关键词必命中」。关键词未明确命中后，可能交给语义分类或灰区复核。

- 离开有效期默认 8 小时，刚回来窗口默认 10 分钟；词表可以修改。
- 明确「在一起」默认持续 150 分钟；已有事件更晚结束时可随事件延长，最长 300 分钟。`together_ttl_minutes` 可调。
- 「在身边」是没有离开记录的默认状态；「在一起」是明确同行 / 相处状态，场景提示不同。面板可手动设置与取消。
- 加速词默认包括「快到家」「马上到」等，对适用的出门 / 路上事件调整加成与剩余时间；默认加速倍数 3、缩短系数 0.5。结束与加速语义需结合完整句判断。

## 约定

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `enable_appointment` | true | 约定识别与到点提醒 |
| `appointment_future_days` | 14 | 带明确日期时的未来日历日范围，0 保留仅本日模式 |
| `appointment_max_hours` | 14 | 没有明确日期的钟点最远小时数 |
| `appointment_max_per_day` | 6 | 每日登记额度，0 不限；每会话队列容量仍为 3 |
| `appointment_lead_enabled` / `appointment_lead_minutes` | true / 2 | 普通约定提前提醒 |
| `appointment_merge_minutes` | 15 | 将附近常规主动消息合并为提前提醒的窗口 |
| `appointment_followup_enabled` / `appointment_followup_minutes` | true / 8 | 到点提醒后未回复的补充提醒 |
| `appointment_max_followups` | 1 | 最多补充次数，0 不补 |
| `appointment_keywords` | 内置词表外的补充 | 扩充支持的事项词 |

支持明天、后天、星期与明确年月日等日期表达。无年份按当前年，裸星期取最近一次（含当天），过去日期不自动顺延；非法、冲突、备选或超范围目标不擅自登记。时间使用 AstrBot 宿主本地时区，部署时需核对。

取消最好同时给出日期、钟点和事项。多候选时不猜「那个会议」指哪条；明确「全部约定取消了」才按范围批量取消。明确改期要求唯一匹配原约定，存在歧义、额度或冲突时保留原状态。

本人明确叫醒请求使用专用到点流程，不提前叫醒，也不重复补叫。普通约定在睡眠中按规则顺延；提前醒来可触发相应补排程。模型异常、发送失败或中途取消不等同于成功投递。

## 睡眠

| 项目 | 默认 |
| --- | --- |
| 晚睡提醒窗口 | 23:00–00:20 |
| 午睡提醒窗口 | 13:00–13:30 |
| 起床时间 | 08:00 |
| 夜晚起点 | 18:00 |
| 白天补觉静音 | 8 小时 |
| 「等会再睡」提醒区间 | 20–60 分钟 |
| 两次睡眠提醒的最小间隔 | 90 分钟 |

晚睡、午睡提醒有各自开关；夜窗提醒与「等会再睡」提醒共用晚睡开关。窗口内去重，待睡提醒另外抽取一次时间。「先不睡 / 不想睡」保持原夜间规则，明确延期表达才建立待睡提醒。

明确「晚安 / 我睡了」进入免打扰；「午睡 / 补觉 / 眯一会」按对应事件处理，不直接等同整夜静音。默认唤醒词为 `我醒了 / 睡醒了 / 醒了 / 起床 / 起来了 / 不睡了 / 睡不着`，也可自定义。疑问、引用、第三方与聊天中提到睡觉不应直接触发本人睡眠状态。

## 控制模型调用和上下文

### 识别开关与额度

| 路径 | 参数 | 默认 |
| --- | --- | --- |
| 事件语义分类 | `enable_llm_event` | true |
| 语义分类模型 | `llm_event_provider` | 空，使用当前会话模型 |
| 事件灰区复核 | `enable_gray_review` | true |
| 事件灰区额度 | `gray_review_per_hour` / `gray_review_per_day` | 6 / 30 |
| 约定灰区额度 | `appointment_gray_per_hour` / `appointment_gray_per_day` | 4 / 10 |

语义模型填写 AstrBot 中对应的服务商 / 模型标识；可以选择适合分类任务的低价模型。只关闭 `enable_llm_event` 不会同时关闭两种灰区复核。若只想让识别走规则，应关闭 `enable_llm_event`、`enable_gray_review`，并将约定灰区额度设为 0；**主动生成与预览仍会调用模型**，这不是整个插件离线运行的开关。

### 主动生成的上下文

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `use_conversation_history` | true | 使用 AstrBot 会话历史 |
| `use_platform_history` | false | 注入实际平台流水 |
| `platform_history_count` | 20 | 平台流水上限；0 不注入 |
| `include_bot_messages` | true | 流水包含 Bot 消息 |
| `include_history_images` | false | 是否携带历史图片 |
| `include_history_think` | false | 是否保留历史思考块 |
| `history_hard_limit` | 120 | 历史硬上限；0 取消此上限 |
| `enable_context_window` | false | 额外启用条数 / 时间窗口裁剪 |

两个历史来源都关闭时，会回退到会话历史。两者同时开启可能带来重叠内容和更多输入。建议按实际需要选来源，避免只为省 token 把必要上下文全部切掉。

窗口由 `context_window_count`、`context_window_hours`、`context_window_min_messages` 控制：条数与小时为上限，最少保留为兜底且不会越过条数上限。时间依赖历史中的 `<system_reminder>Current datetime: ...`；关闭 AstrBot 的当前时间注入后，可能只能按条数裁剪。

这些历史选项针对主动生成路径，正常聊天由 AstrBot 自己管理。各用途的实际输入以请求参数为准，不应把历史设置理解为所有分类与灰区提示词的统一长度控制。

主动消息提示词支持 `{{current_time}}`、`{{unanswered_count}}`、`{{event_hint}}`；平台流水提示词支持 `{{platform_history_lines}}` 以及当前时间、未回复次数；语义分类提示词支持 `{{catalog}}`。面板覆盖保存在插件数据目录的 `web_overrides.json`，备份时应一并保留。

## 分段与面板

分段默认开启，最多 5 段、最小段长 12 字，随机段间延迟 0.8–3.0 秒；也可选 linear / log / fixed 策略。智能分段保护引号、括号、代码块。过短内容不分段；不要在不清楚含义时手动改分段正则。

面板默认 `127.0.0.1:7627`，默认空密码、`allow_embed=false`。远程服务器优先通过 SSH 隧道或带 HTTPS 的鉴权代理访问；若扩大监听范围，先设置密码，并保持不允许任意嵌入。

- **任务**：看状态、约定、最近判定、排程原因；预览、立即发送、重排、重置计数、清事件 / 睡眠、调整在一起状态和会话列表。
- **概率**：预览无事件、有事件、晚睡、补觉曲线；纵轴封顶只影响显示。保存才应用参数。
- **配置**：修改常用参数与提示词；事件规则和监听地址 / 端口等按提示重载。

预览会消耗模型 token；立即发送会实际发送。判定中只有实际执行且有快照的记录可以撤销，状态已变化时拒绝过期撤销。排程诊断只保留每会话最近 20 次内存记录，重载清空；读取它不会调用模型或重新排程。

调试、回放与测试步骤见 [开发验证说明](validation.md)。需要帮助时请到 [GitHub Issues](https://github.com/Mitchell7627/astrbot_plugin_mitchell_minichat/issues) 提交脱敏信息。
