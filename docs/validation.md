本次以 `3f16f4e`（v0.2.10）为基线，保留频率、陪伴提示词及 QQ 平台范围。新增内容尚未部署服务器或发布 GitHub。变更日志中的旧测试数量来自历史说明；其原始测试集不在当前仓库，不能作为本次验收结果。

## 安装与运行

需要 Python 3.12。仓库根目录运行 README 中的虚拟环境安装命令，然后执行 `python -m pytest -q`。`requirements-dev.txt` 固定顶层开发依赖，间接依赖仍由包管理器解析；它不是完整依赖锁文件。云环境也可直接使用 `/workspace/.venvs/minichat/bin/python`。

浏览器测试使用 Playwright 与 Chromium，优先选择 `MINICHAT_CHROMIUM`，其次系统 `chromium`，最后 Playwright 安装的 Chromium。没有浏览器会明确跳过该项，跳过不代表验证通过。CI 配置先安装浏览器再执行测试；本次未在 GitHub 上触发 CI。

测试使用临时数据目录、固定随机源和可控时钟；不修改真实用户数据、不发送 QQ、不调用外部模型。浏览器测试会启动并关闭一个随机本地端口的实际面板，验证任务卡片与三种发送提示。鉴权、配置保存和概率预览也由实际 FastAPI 应用或业务层验证。

## 离线回放

```bash
python tools/replay.py tools/replay-example.json > replay.json
python tools/replay.py tools/replay-example.json --fallback --seed 42 --timezone Asia/Hong_Kong
```

输入 JSON 包含按时间排序的 `events`，每条有 `at` 和 `text`；可选 `until` 指定最后推进到的时间。时间可为 Unix 秒，或**带时区**的 ISO 时间，例如 `2026-11-02T10:00:00+08:00`。同一时刻先处理已到点任务，再处理输入消息。`until` 不得早于最后消息，模拟每 30 秒的过期巡检，单次最多 7 天、2000 次触发，超出时明确失败。

默认时区 `Asia/Hong_Kong`、随机种子 42、16 类界面默认规则；`--fallback` 切换至 8 类文件模板。工具在临时目录运行并自动清理，输出 JSON 到标准输出，日志到标准错误。不读取服务器配置、历史或凭据，不启动 HTTP 面板，不连接模型和 QQ。时间和随机替换仅在这个独立回放进程中生效。

回放使用真实的关键词识别、状态机、调度器和主动生成提示词组装；模型替身只返回固定占位文本，发送替身只记录成功。输出包括每条消息/定时触发后的状态、排程记录、场景提示，以及定时触发时送给模型替身的完整参数。**它验证流程和提示词，不验证模型输出质量或 QQ 投递。** 模型分类和灰区复核在回放中关闭；它们的异步结果一致性由独立回归测试验证。提示词包含输入消息的派生信息，请自行决定是否分享回放结果。

## 新增诊断与兼容性

- `GET /api/status` 新增 `schedule_diagnostics`：按会话 ID 映射到记录数组。
- `GET /api/tasks` 的每个会话新增同名数组。原字段保留。
- 每条记录包含 `at`、`reason`、`next_at`（可能为空）、`steps`。步骤包含 `reason` 和调整后的 `minutes`。每会话最多 20 条，每条最多 8 步；只在内存中保留，重载清空，不增加持久化状态字段。
- 原因涵盖指定延迟、随机采样、事件窗口采样/压窗、恢复旧排程、睡眠提醒对齐、约定优先、最短一分钟、正常回复避让、事件结束恢复/重抽、睡眠免打扰、约定顺延、未回复暂停及承诺唤醒。
- 读取返回深拷贝，不调用模型、不改变排程；记录只含时间和原因，不含消息正文或凭据。任务页展示历史调整链；`next_at` 是该决策当时的目标，不应把历史条目当成当前定时器。
- `POST /api/fire` 保留 `fired`、`sent`、`unanswered`、`next_at`，新增 `delivery_status`（`not_sent` / `partial` / `sent`）、`planned_segments`、`delivered_segments`、`reason`。`sent=true` 表示至少一段被发送接口接受，完整成功请判断 `delivery_status=sent`，不表示用户已读。
- `POST /api/send` 同样新增发送状态与段数。分段字符串返回值保持兼容；内部 `_fire` 现在返回本次调用结果。催睡成功不增加未回复计数，但不再被面板误报为未发送。已通过加载 v0.2.10 原面板实现对照复现：同样发送成功、计数保持 3，原实现返回 `sent=false`，修复实现返回 `sent=true`。
- 请求取消/超时仍走原异常契约；已经发送的内容依现有机制补写历史，取消不伪装成完整成功。

## 验证范围

回归覆盖 16 个配置事件、8 类回退路径、否定/疑问/转述/未来/复合句、在场冲突、睡眠唤醒、跨午夜、多约定、睡眠顺延和旧队列补 ID；也覆盖异步识别过期、撤销冲突、工具结果配对、实际分段失败/取消、并发互斥和卸载清理。

诊断测试核对采样到睡眠再到约定的优先顺序、事件压窗、记录上限、快照隔离与读取无副作用。回放测试禁止 socket 连接并比较两次完整结果。浏览器测试核对新增原因展开及未发送、部分发送、完整发送提示；未使用真实生产配置或在线模型。

## 服务器核对、发布与回滚

服务器 `VM-0-15-debian` 尚无可解析地址及可用 SSH 连接条件，故以下步骤仍未执行：

1. 获得 HostName/IP、端口、用户名和安全配置的访问后，只读核对 AstrBot/Python 版本、容器/服务、时区、插件目录、代码差异与指定时段日志；找回原测试。服务器未提交修改单独保留，不能被当前 checkout 覆盖。
2. 比对服务器的 16 类配置/文件回退、监听会话、提示词覆盖和模型选择，核对实际时区。完整宿主插件页 API、模型生成质量和 QQ 收发需要在隔离测试实例验证；生产只读检查不覆盖这些能力。
3. 在离线测试和隔离宿主验证通过后，准备 GitHub 改动说明、版本号和验证报告，再执行发布。当前阶段不自动推送、打 tag 或提交市场；市场由用户投放。
4. 部署前保留服务器现有代码、配置与插件数据备份，并记录 AstrBot 和 Python 版本。回滚时卸载/停止本插件任务，恢复部署前的插件目录并重载，核对面板与任务恢复。新增诊断仅在内存中，不需要数据迁移；不得用 `git reset --hard` 覆盖服务器本地开发成果。旧版本若需完整恢复运行状态，使用部署前数据备份，而非假定运行期间产生的状态完全相同。
